# 账单合并工具 · 更新记录（CHANGELOG）

**规则：每次更新都递增一个版本号。** 版本号会同时出现在三个地方，便于你随时确认手上这份是不是最新版：

| 出现位置 | 说明 |
| --- | --- |
| 工具页面顶部标题栏 | 打开 index.html 就能看到，如 `v1.1.0` |
| 页面底部小字 | 形如 `版本 v1.1.0（2026-09-21）` |
| 本文件第一条记录 | 与上面两处一致 |

版本号的**唯一来源**是 `core.js` 里的 `VERSION` / `BUILD_DATE`；`index.html`、
`使用说明.txt`、本文件中的版本号必须与之一致（由回归脚本
`.workbuddy/tmp/test_version.js` 自动校验，不一致会报错）。

版本号规则：`v主.次.修`
- **修**（如 v1.1.1）：只修 bug / 改文案，用法不变；
- **次**（如 v1.2.0）：加了新功能或改了默认行为，需要留意；
- **主**（如 v2.0.0）：界面/流程大改。

## v1.5.1 — 2026-09-22

- **修**：**新增计价规则时单价读不到（金额全变 0）**。两个叠加原因：
  ① 新增行的两个价格框按列固定（第 1 格=元/m³、第 2 格=元/m²），但代码不管
  「计量方式」选什么，都把第 1 格当优先单价——选「面积 m²」再把价格填在元/m² 列时，
  工具读的是空着的元/m³ 格，单价就成了 0。现在按计量方式自动对应正确的列。
  ② 计价引擎把「单价 0」当成有效单价，拿到 0 就直接算、永远不会退用另一口径的单价。
  现在 0 或留空一律视为「未启用」，自动落到另一口径。
- **改**：新增规则行的价格框不再预填 0（占位提示改为「元/m³单价」「元/m²单价」），
  切换「计量方式」下拉立即生效。
- **改**：未匹配计价规则的构件只提示一次「未匹配」，不再额外报「缺单价」造成误导；
  数量照常填入台账、单价按 0 记。

## v1.5.0 — 2026-09-21

- **改**：计价方式升级为**双价自动选**。每个产品类型可以同时填「元/m³」和「元/m²」
  两个单价——优先按“计量方式”取数计价；当单据里没有该数量时（比如表里只有体积、
  而该类型按面积计价），**自动改用另一口径的单价**，金额照常算出来。
- **改**：**不再用「板长×板宽」推算面积参与计价**。长×宽是毛面积，异形板（开洞/缺口）
  的实际面积比它小，之前这么算金额会虚高。步骤 3 的「面积/体积互为推算」开关
  默认改为**关**；关着的时候，合并结果里的「单块面积」列只填单据原值，单据没有就空着。
- 缺数量又没填另一口径单价时：台账金额**留空**、汇总按 0 计，并给出明确提示
  （告诉你缺什么、去计价规则里把两个价都填上即可）。
- 影响：以前“只有体积的单据 + 按面积计价”会悄悄用体积顶替面积（或用长×宽推算），
  现在要么填上 元/m³ 的价按体积算，要么明确提示缺数据——不会再算错。
- 回归：`run_tests.js` 全套更新（双价选路、不推算口径、翔安真实数据改按体积计价）。

## v1.4.1 — 2026-09-21

- **修**：导出时勾选「附带原始货单」，用 Excel/WPS 打开后**标题变成 0 或空白**。
  原因是输出的工作簿里 `<calcPr>` 没写“打开时重算”标记，而 ExcelJS 整表复制时
  对**字符串型**公式结果（典型就是出库单标题 `="成品出库单丨"&TEXT(I151,"yyyy年m月d日")&"…"`
  这种 `t="str"` 单元格）会丢掉缓存值，于是打开就显示 0。
  现在导出时写入 `fullCalcOnLoad`，Excel/WPS 打开会**自动重算一次**，标题、合计、
  序号等公式全部正确显示。数值型公式（如 `SUM(E8:E149)`）本来就有缓存，不受影响。
- 回归：新增 `check_ver.js` 版本一致性巡检；`run_tests.js` 全绿。

## v1.4.0 — 2026-09-21

- **导入环节不再“一句提示打死”**（用户报“这份文件识别不了”，实际是文件在第一步就被筛掉了）：
  导入失败时**逐条列出被跳过的条目和原因**（不是 Excel / 是输出文件 / 是 ~$ 临时文件 /
  拖拽没带出文件），并给出可操作的做法（改用「选择文件夹导入」、从资源管理器拖、
  用「选择文件」按钮）。同时：
  - 支持格式从 `.xlsx` 放宽到 **`.xlsx / .xlsm / .xls`**（老式 .xls 排产/出库单也能读）；
  - 拖拽改为**两条通道都收**：`dataTransfer.files`（真实文件）＋ `webkitGetAsEntry`
    （递归读文件夹）。此前只走 entry 通道，凡是拿不到 entry 的拖拽（部分来源的虚拟文件）
    会一个文件都收不到，表现就是“没有可处理的 .xlsx 文件”。
- **楼栋兜底**：有些出库单表里没有“楼栋”列，楼栋只写在文件名里（如
  `20260807-翔安一中12#出库单(1).xlsx` → `12#`）。步骤 3 新增「楼栋兜底」输入框，
  自动从文件名推断（文件名里出现多个不同楼栋时视为歧义不猜），**只在某张表完全没匹配到
  “楼栋”列时补齐，不覆盖表里已有的值**，合并提示里会逐表说明用了兜底值。
- **体积 / 面积按语义分开取，缺的一栏由尺寸推算**：`merge()` 新增 `rowMeta.qty`，
  按源表头判断「单块体积/面积」这一列装的是体积还是面积（如翔安出库单只有「单块体积m³」，
  而钢管桁架板按面积 160 元/㎡ 计价）。台账与汇总据此把数值放进正确的一栏：
  - 源表缺面积 → 按 **板长×板宽** 推算（毛面积，1020×1720 → 1.7544㎡）；
  - 源表缺体积 → 按 **面积×板厚** 推算；
  - 步骤 3 有开关可关闭推算；一旦用到会在台账/汇总提示里写明多少块是推算的；
  - 判定不出语义时**保持旧口径（一个数填两栏）**，既有项目（太和、尚谷大院）数值不变。
- **当天单楼栋发货汇总的体积/面积两列都填**：以前只填计价规则的那一栏（按面积计价时
  体积合计恒为 0）。现在两栏都累计，单价仍按规则的计量方式计算。翔安出库单实测：
  1154 件 / 469.694m³ / 11822.494m²（与前 9 张表的“出库总量 体积”逐张相符）。
- **出库总量校核支持“总量印在表头区”的格式**：有些出库单把
  `出库总量 | 体积 | 57.716m³` 印在第 4 行（表头行之上），此前只在明细区找校核行，
  这类格式校核面板是空的。现在找不到底部校核行时会再看表头区，翔安出库单 9 张表
  全部“标注 = 明细合计 ✔”。
- 回归：`run_tests.js` 5 个脚本全过；太和真实数据 496 件 / 2579.571㎡ / ¥330172.44
  与对账单一致（未受影响）。

## v1.3.1 — 2026-09-21

- **附带原始货单升级为“原格式整表复制”**：此前导出时附上的原始单是重新排版的
  纯数据（格式、公式全丢）。现在改用 ExcelJS 把每张已勾选的原始单**逐格按原样

  - 三个导出（合并明细 / 台账 / 汇总）都走新逻辑，勾选框文案改为
    “附带原始货单（原格式含公式）”；
  - 工具包新增 `exceljs.min.js`（离线本地库，约 0.9MB，需与其它文件放在一起）；
    若该文件缺失或复制失败，自动退回纯数据附加方式并提示，不会导致导出失败。

## v1.3.0 — 2026-09-21

- **汇总按构件类型拆行**：步骤 6 汇总口径升级为 **发货日期 × 楼栋 × 构件类型**——
  同一天同一楼栋发了 PC叠合板、钢管桁架预应力叠合板、PC楼梯时，各占一行

  也支持**直接把文件夹拖进虚线框**。自动跳过输出文件（含“合并/汇总”字样）、
  ~$ 临时文件和非 Excel 文件。
- **导出附带原始货单**：三个导出（合并明细 / 台账 / 汇总）都新增“附带原始货单”
  勾选（默认勾上）——导出的工作簿末尾会附上所有已勾选的原始货单，
  **每张原始单一个工作表**（表名 = 原文件名），发出去对方能直接翻到原始单据。

## v1.2.0 — 2026-09-21

- **新增步骤 6「当天单楼栋发货汇总 & 对账校核」**（合并后可用，原步骤 1-5 全部不变）：
  - 按 **发货日期 × 楼栋** 汇总出库数据：车次数（按送货单张数计）、构件件数、

    同时自动比对“台账合计 vs 汇总合计”，两处金额对不上会立即提示。
